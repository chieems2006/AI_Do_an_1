## 1. Chạy

```bash
cd src && MSA_CATALOG=../data/processed/catalog_v1.parquet MSA_IMAGES_ROOT=../data MSA_CACHE_DIR=../results/cache \
  uvicorn msa.api.main:app --port 8000
curl -F file=@giay.jpg -F k=5 localhost:8000/search/image
curl -X POST localhost:8000/search/text -H 'Content-Type: application/json' \
  -d '{"query":"giày thể thao nữ màu trắng","k":10,"auto_filters":true}'
curl -X POST localhost:8000/compare -H 'Content-Type: application/json' -d '{"product_ids":["fpi_10079","fpi_10080"],"needs":"đi bộ nhiều"}'
```

| Endpoint | Vào | Ra (ngoài khung 5.2) |
|---|---|---|
| `POST /search/image` | multipart `file`, `k`, `product_type` (tuỳ chọn) | items có `score`, `product_type`; lỗi → 400 + `error{code,message}`; top-1 < τ_v → `error.code=not_product` |
| `POST /search/text` | `{query, k, filters{product_type, sub_category, colors[], gender, include_unisex, price_min, price_max, size}, auto_filters}` | `applied_filters` |
| `POST /compare` | `{product_ids[2..3], needs?, use_llm?}` | `table{product_type, columns, rows[{key,label,values}], highlights}`, `recommendation` |
| `POST /qa` | `{question, product_id}` | dùng `msa.rag.pipeline.RAGPipeline` (Chiến) nếu có, ngược lại stub TF-IDF review; `refused` |
| `POST /chat` | `{message, session_id}` | dùng `msa.agent.router.Agent` (Trung) nếu có, ngược lại gọi `LLMGateway` (route `gemini_chitchat`) |
| `GET /health`, `GET /products/{id}` | | |

Log: `logs/requests.jsonl` (endpoint, status, route, source, confidence, latency_ms, n_items, mã lỗi).
Visual backend: `MSA_VISUAL_BACKEND=clip` (CLIP ViT-B/32 HF `openai/clip-vit-base-patch32` + FAISS IndexFlatIP theo từng product_type + type gate zero-shot, ngưỡng 0,5) hoặc `khoa` (module `msa.search.visual` khi ghép).

## 2. Kết quả đo THẬT (`python src/scripts/eval_api.py` → `results/api_eval.json`, 05/11/2026)
Cấu hình: Data v1 (5.021 SP; index ảnh 4.593), CLIP ViT-B/32 CPU, `torch.set_num_threads(2)`, τ_v = 0,25; đo trong tiến trình (TestClient) trên máy 2 CPU **đang chạy song song benchmark text-embedding và tác nhân khác** (latency là cận trên).

### 2.1 `/search/image` (US_30) – 80 truy vấn
Truy vấn: 60 ảnh FPI **không có trong catalog** (20/nhóm giày, quần áo, phụ kiện; seed 42) + 20 ảnh mũ leave-one-out (catalog đã lấy hết mũ FPI nên không còn ảnh held-out). Ảnh đều là studio 60×80 → **không đại diện ảnh người dùng thật**.

| Nhóm | n | Latency p50 / p95 (ms) | Cross-type error@5 | (không gate) | Sub-category P@5 | Type gate đúng |
|---|---:|---:|---:|---:|---:|---:|
| footwear | 20 | 505 / 1.131 | 0,00 | 0,00 | 0,91 | 100% |
| clothing | 20 | 447 / 894 | 0,00 | 0,00 | 0,91 | 100% |
| accessory | 20 | 323 / 1.463 | 0,00 | 0,00 | 0,99 | 100% |
| headwear (LOO) | 20 | 458 / 973 | 0,06 | 0,02 | 0,89 | 90% |
| **Tổng** | **80** | **393 / 1.106** (max 2.031) | **0,015** | 0,005 | **0,925** | **97,5%** |

- Latency: 97,5% truy vấn < 1,5 s (đạt chỉ tiêu ở p95); 2 truy vấn vượt (max 2,0 s) khi CPU bị chia.
- Cross-type error@5 = 1,5% ≤ 10% ✅. Type gate làm **tăng** lỗi ở mũ (0,02 → 0,06: 2 ảnh mũ bị gate nhận là phụ kiện, conf 0,66 và 0,36) → gợi ý cho Khoa: nâng ngưỡng gate hoặc chỉ lọc khi conf ≥ 0,8 (cần đo lại).
- **Recall@5 CHƯA ĐO**: cần eval_visual có cặp truy vấn ↔ đúng sản phẩm (Khoa, N9–N10) + ảnh ngoài đời (80–100 ảnh tự chụp). Sub-category P@5 chỉ đo "cùng loại lá", không phải "cùng sản phẩm".
- Không truy vấn nào dưới τ_v = 0,25 (top-1 TB 0,96) → với CLIP B/32, τ_v = 0,25 quá thấp để chặn ảnh "không phải sản phẩm"; cần hiệu chỉnh trên ảnh ngoài phạm vi.

### 2.2 `/search/text` (US_37) – 15 truy vấn lọc thật (k = 20)
**15/15 truy vấn có kết quả, 300/300 kết quả thoả bộ lọc (0 vi phạm)**; latency p50 20 ms, p95 29 ms. Bộ lọc kiểm: product_type, sub_category, màu (theo họ màu, nhập tiếng Việt), giới tính (± unisex). **Giá và size không kiểm được trên dữ liệu thật** (catalog thiếu 100%) → đã kiểm bằng 15 truy vấn trên catalog tổng hợp trong test (có lọc giá, size).

### 2.3 `/compare` (US_38) – 20 nhóm thật (16 nhóm FPI + 4 nhóm Shopee/ViMRHP, 2–3 SP, cùng nhóm)
So từng ô với **dữ liệu gốc** (parquet FPI: tên, màu, giới tính, usage, season, year; JSON ViMRHP: tên, rating TB, số review; ô không có nguồn phải là "chưa có thông tin"): **370/370 ô khớp (100%), 20/20 nhóm khớp 100%**; latency p50 3,4 ms. So khác nhóm (vd. giày với áo) → 400 `mixed_types`.

## 4. US_39 – gợi ý dựa trên bảng
`recommend(table, needs, gateway=None)`: chấm điểm theo luật (ngân sách, màu, giới tính, mục đích dùng, rating) – mỗi lý do trích nguyên ô của bảng; nếu `use_llm=true` thì gửi Gemini **chỉ bảng + nhu cầu**, sau đó `check_grounded` bắt mọi con số / product_id / khẳng định "chất liệu/size/giá" không có trong bảng → loại câu LLM, dùng câu theo luật. Test: câu LLM bịa ("đế cao 5cm, giá 123456") bị loại; câu chỉ trích ô bảng được giữ. **Chưa đo trên Gemini thật** (quota).

## 5. Việc còn lại
- Ghép `VisualSearcher` của Khoa, `RAGPipeline` của Chiến, `Agent` của Trung (đã có điểm cắm; tự dùng khi import được).
- Đo Recall@5 trên eval_visual + ảnh ngoài đời; hiệu chỉnh τ_v và ngưỡng type gate; đo lại latency trên máy rảnh và qua HTTP thật (uvicorn).
- Bổ sung giá/size (crawl VN) để kiểm bộ lọc giá/size trên dữ liệu thật; re-rank kết hợp điểm ảnh + text (US_45, I11).
